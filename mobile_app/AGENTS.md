# AGENTS.md — دليل الوكيل الذكي لمشروع FinAcc

> **اقرأ هذا الملف أولًا وقبل أي شيء آخر.** هو كل ما تحتاجه لتبدأ العمل بفهم صحيح وبلا تخبط أو غموض.

## 1) ما هذا المشروع؟

**FinAcc «المُحاسِب الشخصي»** — تطبيق Flutter **عربي RTL أوفلاين-أولاً** للمحاسبة والمخزون للتجار الصغار:
أصناف ودفعات بتواريخ صلاحية (FEFO) + باركود، عملاء/موردون بأرصدة بعملات متعددة، كاشير بيع (نقدي/آجل/مختلط) وعروض أسعار قابلة للتحويل، مشتريات بتكلفة WAC، مرتجعات مرتبطة بالفواتير، صندوق ومدفوعات.
كل البيانات في **SQLite محلي 100%** (WAL مفعّل دائمًا + ترقيم مستندات ذرّي `doc_sequence`). لا سيرفر ولا شبكة.

## 4) قواعد ملزمة (لا تُخالف أبدًا)

1. **عربي أولًا**: RTL + خط **Cairo** (مع NotoSansArabic للأرقام الجدولية — DS-18n) + لون الهوية `0xFF1976D2` (هوية Simple Invoice Manager منذ V3). ممنوع نص hardcoded في أي شاشة. **مرجع التصميم الإلزامي: `docs/sim-design-reference.md`** — يُراجع قبل بناء أي واجهة وتُقارن به لقطات التحقق الحي.
2. أي نص جديد = **مفتاحان في arb (عربي/إنجليزي)** ثم `flutter gen-l10n` مباشرة.
3. **قواعد المحاسبة** (SRS §5.4): ترقيم ذرّي INV/QTE/PUR/SRN/PRN/RVT/PMT • معاملات ذرّية • **لا مخزون سالب** • FEFO للدفعات • WAC بخصم رأس موزّع pro-rata • **FR-08-09**: ممنوع حفظ بعملة بلا سعر صرف لليوم.
4. **الهيكل**: ViewModel = `ChangeNotifier` يُنشأ في الشاشة عبر `ChangeNotifierProvider.value`. المستودعات تُؤخذ **من `AppController` حصرًا**.
5. **الملفات المشتركة** (الراوتر / AppController / pubspec / arb): عدّلها بأقل قدر ممكن، وفي العمل المتوازي وكيلٌ واحد فقط يلمسها في كل موجة.
6. دفعة صلاحية تُسجّل عند الشراء، وتُستهلك بالبيع FEFO — لا استثناءات. **الرصيد الافتتاحي للمتتبع يُدفَّع دفعةً بصلاحية 9999-12-31** (بلاها يُرفض البيع بمتاح = 0).
7. **الحزام المزدوج: اختبارات + تحقق حي من المتصفح (قرار 2026-10-07، حُدّث بالجولة 14 ثم V3)**: حُذفت اختبارات الوحدات يوم 2026-10-07 (مجلد `test/` + `flutter_test` + `sqflite_common_ffi`) لأن 414 اختبارًا أخضر لم تمنع أخطاء تكامل حية (متاح = 0، قوائم لا تتحدث، نوافذ تحت الشريط) بينما كشفها التحقق من المتصفح فورًا وكشف خامسًا لم تتنبأ به الاختبارات إطلاقًا — ثم **استُردت بالكامل بالجولة 14** وهي اليوم **799 اختباراً أخضر (V3: 792 + 7 لـVM مركز المعاملات)**، وصارت بوابة إلزامية: `dart analyze` 0/0 + `flutter test` كاملة خضراء في كل جولة، وCI تشغّلها قبل بناء APK (`Test gate` في `.github/workflows/build-apk.yml`). التحقق الحي من المتصفح يبقى **البوابة النهائية قبل أي إصدار** وللدمج الكبير:
   ```bash
   bash scripts/build-flutter-web.sh        # ابنِ المعاينة
   # ثم agent-browser: فتح جذر البوابة / مباشرة (R22) + enable accessibility
   # ثم رحلة المستخدم الحقيقية (تأسيس ← شاشة المهمة ← حفظ ← تحقق بصري/OCR)
   ```
   أدوات موثوقة داخل Flutter Web: فعّل شجرة الوصولية `[aria-label="Enable accessibility"][0].click()` ثم `.click()` على `flt-semantics[role=button]`، أو إحداثيات فأرة دقيقة `mouse move x y` + `down/up`. النص العربي داخل الحقول = `focus()` ثم `keyboard inserttext`. اللقطات تُحلل بـ `scripts/ocr-boxes.py` (tesseract ara+eng) وتحليل بكسلات PIL.
   شبكة أمان: الاختبارات مؤمّنة الآن في git نفسه (تُسلّم كل جولة خضراء) — لم تعد هناك نقطة استعادة خارجية.

## 8) محظورات

- نص واجهة hardcoded أو إنجليزي داخل الشاشات.
- Mock/بيانات مزروعة تبقى بعد إغلاق الشريحة (SRS §9: تُستبدل بربط حقيقي داخل نفس الشريحة).

- لقطات شاشة أو ملفات مؤقتة أو سجلات عمل شخصية داخل git.
- إيداع مخرجات بناء أو ثنائيات في git (`public/mobile_app/` أو APK في `public/downloads/`) — تُبنى بالسكربت أو عبر CI (R21).

## 9) جولة تحقق سريعة (smoke) من المتصفح بعد أي جولة

**ابنِ المعاينة وتحقق من المتصفح قبل أي إصدار** (قاعدة §4-7 — بعد بوابتي analyze والاختبارات الخضراء) ← رحلة: Onboarding (إنشاء منشأة + PIN) → الداشبورد (بلاطات الوصول الأربع) → المخزن (صنف متتبع بكمية افتتاحية) → **البيع: فاتورة كاملة تنجح ويتراجع المخزون** → الأطراف (تسجيل عميل يظهر فورًا في القائمة). إن انكسر أي حلقة فأصلح قبل أي تسليم.

## 10) دروس ميدانية من الجولات الحية (لا تكررها)

- **انزياح شجرة الوصولية في RTL (خلل محرك Flutter Web)**: المحرك يضع `flt-semantics-host` عند حافة RTL بخاصية `direction: rtl` فتنزاح عقد الوصولية عن مواضعها البصرية وتخطف نقرات عناصر خاطئة — كان النقر على زر «الرئيسية» يفتح «المزيد»! **الإصلاح مثبّت في `web/index.html`** (CSS يعيد الـhost لموضعه بـLTR) — لا تحذفه أبداً في بناء الويب، ولا أثر له على أندرويد.
- **تبديل التبويبات لا يُحدث القوائم**: فروع StatefulShellRoute تُستعاد من IndexedStack بلا rebuild ولا didPopNext — قوائم/محاور الإحصاءات تعرض بيانات قديمة بعد ترحيل فاتورة في فرع آخر. **الحل القياسي**: غلّف جسم كل شاشة قائمة/محور بـ `RefreshOnActive` (`lib/ui/core/widgets/refresh_on_active.dart`) بنمط مسارها (مثل `^/inventory/items$`) — مربوط حالياً في: home وinventory وsell hub وitems وinvoices وquotations. أي شاشة قائمة جديدة **إلزامياً** تأخذ نفس الغلاف.
- **القوائم ذات المسارات الفرعية لا تُعاد بناؤها عند الرجوع** (go_router يستعيد عنصر المكدس) → غلّفها بـ `RefreshOnReturn` (`lib/ui/core/widgets/refresh_on_return.dart`) وإلا ظهرت بيانات قديمة بعد الحفظ.
- **`showModalBottomSheet` داخل هيكل التبويبات**: `useRootNavigator: false` حصرًا — وإلا نزلت النافذة من أسفل الشاشة خلف شريط التنقل.
- **`extendBody: false`** في الهيكل: أي محتوى أسفل القوائم كان يختفي خلف الشريط.
- **حقول Flutter Web تختفي من DOM عند خروجها من الشاشة** — للوصول لحقل خارج الشرح: `Tab`/`Shift+Tab` يمرّره للعرض، والسحب يحتاج أحداث حركة متدرجة.
- **لا تنقر «Enable accessibility» إلا لضرورة قصوى**: تفعيلها مرة واحدة يغيّر سلوك الإدخال لكل ما بعدها في الجلسة — تظهر مرايا `flt-semantics` input منزاحة RTL تخطف نقرات الحقول وتُفشل مزامنة النص إلى المتحكمات (typing يظهر في DOM لكن «الاسم مطلوب» يظل). الوصفة العاملة بدونها: انقر الحقل بموضعه البصري (فحص مدخلات DOM بعد النقرة: يجب أن تظهر input/textarea فوق الشاشة) ثم `keyboard type` (يدعم العربية). `CDP insertText` يذهب لبروكسي مخفي (y≈-9456) ولا يصل للمتحكم. النماذج ترتد للتمرير للحقل غير الصالح عند فشل الحفظ — لا تعتبرها فشل تمرير.
- **وصفة ملء الحقول المثبتة حياً (R20 — تعقيب الوصفة أعلاه)**: ضبط `input.value` عبر JS ثم إطلاق حدث `input` **لا يتزامن مع Flutter** (يصفّره فوراً). المسار الموثوق عبر CDP مع تفعيل الوصولية: `python3 scripts/cdp-touch.py tap X Y` بمركز مستطيل حقل DOM الظاهر (getBoundingClientRect — الوصولية مفعلة تخلق inputs حقيقية بمواضعها البصرية) ثم `python3 scripts/cdp-touch.py insert "النص"` — مُجرّبة على اسم المنشأة وحقلي عبارة المرور معاً برحلة R20. أزرار لوحة أرقام PIN تكشف أرقامها عبر textContent لا aria-label — طابق الاثنين. `.click()` على آخر عقدة `flt-semantics[role=button]` مطابقة للنص يعمل عبر الشاشات كلها بعد تفعيل الوصولية (تأكيد درس R19).
